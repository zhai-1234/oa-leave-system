# 零基础先导课：先学会看懂一条请求

## 1. 先不用急着看完整代码

这个项目有几千行代码。零基础直接从头读到尾，通常只会看到大量陌生英文。

正确方法是先回答一个问题：

> 我在页面上点一下按钮，程序到底发生了什么？

学会追踪一条请求，再追踪第二条、第三条，代码就会逐渐变成熟悉的道路。

## 2. 用餐厅理解系统

| 系统里的东西 | 可以理解成 |
| --- | --- |
| 浏览器页面 | 餐厅的菜单和点餐表 |
| 前端 JavaScript | 服务员，负责接收你的操作并传话 |
| HTTP 请求 | 点菜单，从顾客送给后厨 |
| FastAPI | 前台，决定订单交给哪个部门 |
| `server.py` | 真正处理请假业务的老后厨 |
| 数据库 | 仓库和账本，保存账号、请假单和余额 |
| HTTP 响应 | 做好的结果，从后厨送回顾客 |
| JSON | 一种双方都能看懂的结构化纸条 |

你点“提交请假”后，并不是浏览器自己批准了申请。浏览器只是把数据包装成请求，送到后端，后端再写数据库。

## 3. 先认识六个词

### 3.1 变量

变量就是给一份数据起的名字。

```python
name = "张晓雨"
days = 2
```

可以理解成两个盒子：

```text
盒子 name 里放着文字：张晓雨
盒子 days 里放着数字：2
```

### 3.2 函数

函数是一段“可以被叫去干活”的代码。

```python
def add(a, b):
    return a + b
```

可以理解成一台机器：

```text
投入 a 和 b
机器执行 a + b
把结果返回
```

函数定义时不会自动执行。必须有人调用它，例如 `add(1, 2)`。

### 3.3 对象

对象是一组有名字的数据。

```javascript
var user = {
  username: 'employee',
  role: 'employee'
}
```

可以理解成一张资料卡：

```text
账号：employee
角色：employee
```

### 3.4 数组

数组是一排数据。

```javascript
var requests = [
  { request_no: 'QJ001', days: 1 },
  { request_no: 'QJ002', days: 2 }
]
```

可以理解成一叠请假单。

### 3.5 JSON

JSON 是前后端传数据时常用的一种文本格式，长得像对象和数组：

```json
{
  "leave_type": "事假",
  "start_time": "2026-11-10",
  "reason": "去银行办事"
}
```

浏览器把 JSON 发给后端，后端读取里面的字段。

### 3.6 数据库表

数据库表类似 Excel 表格。

`users` 表的一部分：

| id | username | name | role |
| --- | --- | --- | --- |
| 1 | employee | 张晓雨 | employee |
| 2 | approver | 王主管 | approver |

`leave_requests` 表保存请假单，`leave_balances` 表保存余额。

## 4. 前后端到底是谁

### 前端

运行在浏览器里的代码，主要在 `static/` 目录。

- 显示页面。
- 接收点击和输入。
- 发送 HTTP 请求。
- 把后端结果显示到页面上。

### 后端

运行在 Python 服务里的代码，主要是 `server.py`、`fastapi_app.py`、`ai_assistant.py`。

- 判断用户是否登录。
- 检查权限和业务规则。
- 查询、插入、修改数据库。
- 把结果返回给前端。

### 数据库

保存在 `leave_system.db` 文件里。

- 账号在这里。
- 请假单在这里。
- 假期余额在这里。
- 关闭浏览器、重启电脑后数据仍然存在。

## 5. 一个 URL 请求长什么样

前端代码中经常出现：

```javascript
fetch('/api/requests')
```

可以读成：

> 浏览器，请向当前网站的 `/api/requests` 地址发一个请求。

`GET` 通常表示“读取数据”：

```text
GET /api/requests
```

`POST` 通常表示“提交数据或执行动作”：

```text
POST /api/requests
```

请求后面还可能带一段 JSON，例如请假表单内容。

## 6. 前端怎么发请求

真实代码在 `static/vue/core.js`：

```javascript
VP.api = async function api(url, opt) {
  var options = Object.assign({ headers: { 'Content-Type': 'application/json' } }, opt || {});
  var r = await fetch(url, options);
  var d = await r.json();
  if (!r.ok) {
    throw Error((d && (d.error || d.detail)) || '操作失败');
  }
  return d;
};
```

逐行翻译：

1. `VP.api` 是一个函数，所有页面都可以调用它。
2. `url` 是要访问的接口地址。
3. `opt` 里可以放请求方法、请求体等设置。
4. `fetch(url, options)` 真正把请求发给后端。
5. `await` 表示等待网络结果，不必冻结整个浏览器。
6. `r.json()` 把后端返回的 JSON 文本转换成 JavaScript 数据。
7. `r.ok` 为假表示 HTTP 状态不是成功，例如 400、401、403、500。
8. 失败时抛出错误，页面可以捕获后显示提示。
9. 成功时返回 `d`，供页面使用。

可以把 `VP.api` 理解成全网站统一的“传菜员”。

## 7. 后端怎么接住请求

这个项目接普通请求的入口在 `fastapi_app.py`：

```python
@app.api_route("/{path:path}", methods=["GET", "POST"], include_in_schema=False)
async def compatibility_route(request: Request, path: str):
    body = await request.body()
    raw_path = request.url.path
    if request.url.query:
        raw_path += "?" + request.url.query
    return run_legacy(request.method, raw_path, request.headers, body)
```

这里的 `path:path` 表示“任意路径”。所以除了前面专门注册的 AI 接口，普通业务请求都会进入这里。

然后 `run_legacy()` 会创建一个旧处理器对象，把请求转给旧代码：

```python
handler = object.__new__(legacy.Handler)
handler.path = path
handler.command = method
handler.rfile = BytesIO(body)
handler.wfile = BytesIO()
```

最后调用：

```python
if method == "GET":
    handler.do_GET()
elif method == "POST":
    handler.do_POST()
```

这里不需要背语法，只需要记住：

```text
FastAPI 接住请求
-> run_legacy 包装请求
-> GET 调用 do_GET
-> POST 调用 do_POST
-> 旧 server.py 继续处理业务
```

## 8. 回答之前的第一题

问题：

> 浏览器访问 `/api/requests` 后，请求经过哪些函数才能真正进入业务逻辑？

零基础版答案：

```text
页面调用 VP.api()
-> fetch 发出请求
-> FastAPI 的 compatibility_route()
-> run_legacy()
-> Handler.do_GET()
-> /api/requests 对应的查询代码
```

如果请求是提交请假，也就是 `POST /api/requests`，最后一步会换成 `Handler.do_POST()`。

不需要先理解里面每一行，只要知道“谁是入口，谁把请求交给下一位”就够了。

## 9. 为什么有些文件存在但页面没有

浏览器不会自动扫描项目目录里的所有 JavaScript。只有 `index.html` 用 `<script>` 写出来的文件才会被加载。

当前 `static/index.html` 加载了：

```html
<script src="/vue/pages-employee.js"></script>
<script src="/vue/pages-approver.js"></script>
```

没有加载：

```html
<!-- 实际文件存在，但这里没有这一行 -->
<script src="/vue/pages-attendance.js"></script>
```

所以 `pages-attendance.js` 里面的考勤组件根本不会进入浏览器。再加上路由表没有登记考勤页面，后端也没有考勤接口，这个功能就无法使用。

## 10. 回答之前的第二题

问题：

> `pages-attendance.js` 文件明明存在，为什么考勤页面仍然打不开？

零基础版答案：

> 因为网页入口没有加载这个文件，路由也没有登记考勤页面，后端也没有对应接口。三个环节都缺，所以它只是留在目录里的半成品代码。

判断功能是否可用，可以记成四问：

```text
文件加载了吗？
路由登记了吗？
后端接口存在吗？
数据库有地方存吗？
```

任何一项缺失，功能都可能不可用。

## 11. 审批通过为什么会改数据库

审批员点击“批准”后，页面发送：

```text
POST /api/admin/requests/{id}/action
```

后端找到对应的 `Handler.do_POST()` 分支，然后做几件事：

1. 确认当前用户是审批员。
2. 确认这张申请属于他的审批范围。
3. 确认不是审批自己的申请。
4. 确认申请还没被处理，并且余额足够。
5. 把 `leave_requests` 里的状态改成 `approved`。
6. 在 `approval_logs` 里新增一条审批记录。
7. 从 `leave_balances` 里扣掉对应天数。
8. 在 `notifications` 里新增一条通知。
9. 返回成功结果给页面。

## 12. 回答之前的第三题

问题：

> 审批通过一张请假单后，至少涉及哪 4 张表的变化？

零基础版答案：

```text
leave_requests    状态变为已通过
approval_logs     新增一条审批日志
leave_balances    扣减假期余额
notifications     新增一条消息通知
```

这四处分别对应“主单结果、审批证据、余额结果、用户告知”。

## 13. 现在应该怎样读代码

不要从第一行开始逐行读。使用“追踪法”：

1. 先找一个页面按钮。
2. 找到按钮点击后调用的函数。
3. 找到函数里请求的 URL。
4. 在 `server.py` 里搜索这个 URL。
5. 找到对应分支后，再看它读了哪些表、写了哪些表。
6. 最后回到页面，看返回结果被显示在哪里。

一次只追一条线。追完三条，项目的骨架就会开始清楚。

## 14. 本课只要求掌握三件事

1. 前端负责页面和发请求，后端负责规则和数据库。
2. `VP.api()` 发请求，FastAPI 兼容路由把它交给旧 `Handler`。
3. 文件存在不等于功能可用，必须加载、路由、接口、数据表全部接通。

只要能用自己的话复述这三点，就已经完成本课。

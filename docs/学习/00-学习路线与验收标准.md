# 请假系统-AI 学习路线与验收标准

## 目标

最终目标不是“知道每个文件做什么”，而是能够独立完成下面四件事：

1. 从任意页面或接口出发，完整追踪一次业务请求。
2. 解释每条数据为什么出现在数据库、为什么被修改。
3. 判断一个页面功能是否真正接线，而不是只看源码是否存在。
4. 在不破坏既有规则的前提下新增或修改一个功能，并用测试验证。

## 每一课怎么学

每一课都按同一顺序进行：

1. 先看运行路径：用户操作如何进入代码。
2. 再看输入与输出：前端传什么，后端返回什么。
3. 然后看规则：哪些条件会拦截、改写或分支。
4. 接着看数据：哪些表被读，哪些表被写。
5. 最后做自测：不看源码复述流程，再完成一个最小改动题。

## 当前项目基线

- 运行形态：FastAPI 承载 AI 路由，普通业务通过兼容层调用旧 `server.py`。
- 前端形态：Vue 3 全局构建，无打包步骤，Hash 路由，本地静态资源。
- 默认数据库：`leave_system.db`，结构由 `db.py` 初始化并做增量补列。
- 账号模型：数据库只有 `employee` 和 `approver` 两种 `role`。
- 实际加载页面：登录、员工请假、审批、返岗续假、HR 汇总、代理、AI。
- 未加载页面：考勤、加班、统计、员工档案。源码存在，但 `static/index.html` 没有加载对应脚本。
- 重要事实：部分已加载页面仍调用了当前后端不存在的接口，不能因为按钮存在就认为功能可用。

## 当前验证基线

- `tests.test_core`：5 项通过。
- `tests.test_ai_assistant`：13 项通过。
- `tests.test_api`：5 项通过，使用独立进程运行。
- `tests.test_phase1_fastapi` 和 `tests.test_phase2_security`：当前虚拟环境缺少 `httpx2`，无法导入 `TestClient`。
- 一次性运行全部测试会出现临时数据库隔离问题：前一个测试类清理目录后，后一个类沿用了已加载的 `db.DB_PATH`。这些测试应按模块分别运行，或后续修正测试初始化方式。
- `static/vue` 下 14 个 JavaScript 文件均通过 `node --check`。

## 结业标准

不借助源码，能够完成以下任务：

1. 用两分钟讲清整个系统架构。
2. 从 `POST /api/requests` 一路讲到所有被写表。
3. 从审批按钮一路讲到余额、日志和通知的变化。
4. 说清 AI 问答、预审、智能填单分别在什么情况下使用规则、LLM 或向量检索。
5. 识别出页面文件存在但未加载、接口调用存在但后端缺失、字段存在但数据库无来源三类问题。
6. 独立新增一个可运行的小功能，并补充测试。
